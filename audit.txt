Toolity.in — Accessibility Audit
================================
Date: 20 Oct 2026 · Audited at commit f51626c · Fixes applied same day (see "Re-audit" at the end)
Target: WCAG 2.2 Level AA (as promised on /accessibility/)

Method
------
1. Automated: axe-core 4.10.2 (wcag2a/aa, wcag21a/aa, wcag22aa, best-practice) run in headless Chrome
   at 1280×900, light theme, on 15 representative pages:
   / · /tools/ · /media/ · /media/image-compressor/ · /docs/images-to-pdf/ · /labs/qr-code-generator/ ·
   /dev/code-formatter/ · /data/csv-viewer-editor/ · /games/2048/ · /widgets/countdown/ ·
   /widgets/countdown/embed/ · /blog/ · /404.html · /accessibility/ · /contact/
2. Static sweep of all 193 HTML files + main.css + main.js (lang, landmarks, headings, alt, labels,
   tabindex, iframe titles, focus styles, reduced motion, ARIA patterns).
3. Contrast maths on the design tokens for both themes.
4. Manual code review of the shared pieces every page inherits: header, footer, search, mobile drawer,
   toast, dropzones, tool-page template.
Not covered: screen-reader walkthroughs, 142 tool pages not in the sample, the 4 widget embeds beyond
countdown, dark theme under axe (token maths done instead), zoom/reflow at 400%.

Findings (ordered by impact × reach)
------------------------------------

F1  [serious · every page]  --text-muted and --brand fail 4.5:1 on light backgrounds    WCAG 1.4.3
    --text-muted #92969B on #FFFFFF = 2.97:1, on --surface #F7F7F5 = 2.77:1
    --brand      #F4511E on #FFFFFF = 3.48:1, on --surface          = 3.24:1
    White text on --brand (primary buttons) = 3.48:1
    Where it bites (axe counts in the 15-page sample):
      .tools-index-cat 160× (new today) · .section-eyebrow 5×/page · .pane-badge · .brand-tld ".in" ·
      .footer-copy + .footer-legal links · .form-helper / .form-label-desc · .video-drop-subtitle ·
      table .th · .tools-index-chip (active) · .nav-link (active) · .btn-primary-signal · .editorial-brand-badge
    Most of these are ALSO small text (10.9–13 px) so the 3:1 large-text exemption never applies.
    Fix (tokens, not components — one change fixes ~90%):
      light --text-muted  #92969B → #6B7075  (4.9:1 on white, 4.6:1 on surface)
      light --text-secondary is fine (5.78:1) — leave.
      --brand as TEXT on light: use a darker ink variant, e.g. --brand-ink #C63D0F (4.9:1 on white) for
        eyebrows, chips, active nav link, badges, links; keep #F4511E for fills, borders, icons, focus rings.
      White-on-brand buttons: either --brand-ink fill for text buttons, or bump button text to ≥ 18.66px bold
        (large-text rule, 3:1 is then enough). The darker fill is the smaller change.
    Dark theme needs nothing.
    Verify: re-run axe on /tools/ and /media/image-compressor/ — color-contrast should drop to ~0.

F2  [serious · every page]  Toast is not announced                                         WCAG 4.1.3
    components/footer.html: <div id="tool-toast" class="tool-toast"> has no role / aria-live.
    "Copied", "Downloaded", "Error: …" never reach screen-reader users.
    Fix: add role="status" aria-live="polite" (and aria-atomic="true") to #tool-toast. 1 line, 1 file.

F3  [moderate · 192 pages]  No skip link                                                    WCAG 2.4.1
    Only /labs/pomodoro-timer/ has one. Keyboard users tab through logo + 8 nav links + search + theme on
    every page before reaching the tool. Landmarks exist, so AT users can bypass; sighted keyboard users can't.
    Fix: in components/header.html add as first child
      <a href="#main" class="skip-link">Skip to content</a>
    give <main> id="main" in templates/tool-page.html + blog-post.html (then re-gen pages, or sed the 190
    existing <main> tags), and a .skip-link style that is visually hidden until :focus. ~8 lines total.

F4  [moderate · every page]  Footer heading order h2 → h4                                   WCAG 1.3.1 (best-practice)
    components/footer.html uses <h4 class="footer-heading"> under pages whose last heading is h2.
    Fix: change the 3–4 <h4> to <h2> (or <h3>), keep the class for styling. No visual change.

F5  [moderate · site-wide]  prefers-reduced-motion is partial                                WCAG 2.3.3 (AAA) / best-practice
    main.css handles body, hero buttons and empty-state icons only. Not handled:
      - hero waves canvas (initHeroWaves) animates regardless of the OS setting
      - the 3 tool CSS files with @keyframes / animation:
      - transforms on hover (translateY / scale) across .btn-icon-pill, cards, result items, the new nav search width transition
    Fix: one global rule at the end of main.css
      @media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important; transition-duration: 0.01ms !important; scroll-behavior: auto !important; } }
    plus `if (matchMedia('(prefers-reduced-motion: reduce)').matches) return;` at the top of initHeroWaves.

F6  [moderate · site-wide]  Focus visibility relies on browser defaults                      WCAG 2.4.7 / 2.4.11
    Explicit :focus-visible styles exist for ~10 components. Everything else (nav links, footer links, chips,
    .btn-pill, .btn-icon-pill, segmented controls, selects) shows the UA ring, which on a white/frosted surface
    is thin and sometimes clipped by border-radius / overflow:hidden parents. Six `outline: none` rules exist
    (.minimal-search-input, .select-clean, .pane-editor, .textarea-clean, two .dragover) — the first four are
    inputs whose wrapper shows focus-within, OK; verify .pane-editor and .select-clean actually have a wrapper ring.
    Fix: one global rule
      :focus-visible { outline: 2px solid var(--brand); outline-offset: 2px; border-radius: inherit; }
    then delete the per-component copies that are identical.

F7  [moderate · mobile]  Drawer focus management                                             WCAG 2.4.3 / 2.1.2
    openMenu() sets aria-expanded and locks scroll but: focus stays on the hamburger, Tab moves behind the
    overlay, focus is not returned to the trigger on close. Esc works.
    Fix (~6 lines): on open → `drawer.querySelector('input,a,button').focus()`; set `main.inert = true` and
    `footer.inert = true` (native, no trap code); on close → remove inert, `toggleBtn.focus()`.

F8  [critical by axe, low reach · /games/2048/]  role="grid" with no rows                    WCAG 1.3.1
    #board is role=grid but children are plain tiles. Screen readers announce an empty grid.
    Fix: either drop role=grid and use role="application" aria-label + an aria-live="polite" score/last-move
    region (simplest; moves are keyboard-driven anyway), or wrap tiles in role=row / role=gridcell.

F9  [minor · widget embeds]  /widgets/*/embed/                                               best-practice
    <main role="region"> (role not allowed on main; drop it), no h1, no landmark (axe sees the role override).
    Embeds are intentionally chrome-less; an sr-only <h1> with the widget name and removing role="region" is enough.

F10 [gap · all tool forms]  No programmatic error association                                WCAG 3.3.1 / 3.3.3
    0 uses of aria-invalid / aria-describedby / aria-errormessage anywhere. Validation messages (bad URL, file
    too large, unsupported type) are shown visually and/or via toast only (and toast is silent — F2).
    Fix F2 first (covers most). Then in tool-common.js add a 5-line helper `setFieldError(input, msg)` that
    toggles aria-invalid and points aria-describedby at the helper <p> — adopt per tool over time.

F11 [introduced today · header]  #nav-search is a <div aria-label>                          axe aria-prohibited-attr
    aria-label on a role-less div is ignored by AT. The inner .site-search already has role="search".
    Fix: remove aria-label from #nav-search (header.html, 1 attribute).

F12 [observations, not failures]
    - Tiny type: .tools-index-cat 10.9px, .pane-badge 11.8px, .form-helper 11.8px. Legal at AA once contrast
      passes, but 12px is a sensible floor — F1's token fix should pair with a 0.75rem minimum.
    - 37 aria-live regions exist (good), but none are checked for "polite vs assertive" appropriateness —
      progress bars that update every frame should be aria-live="off" with a summary announced on completion.
    - <video>/<audio> outputs have no <track>; acceptable (user-supplied media), state it on /accessibility/.
    - /accessibility/ promises WCAG 2.2 AA. Until F1–F4 ship, it should list contrast + skip link under
      "known limitations" to stay honest.

       New --brand-ink (#C63D0F light / #FF6A2A dark) for brand used AS TEXT: eyebrows, badges, active nav link,

Remaining / known limitations (be explicit on /accessibility/)
  1. Widget EMBED title (.w-title) uses the embedder's `accent` parameter; default F4511E on white = 3.47:1.
     This is the embedder's colour choice. Options: change the default accent to C63D0F (affects existing embeds
     that never set one) or document it. Left as-is pending a product call.
  2. 142 tool pages were not individually scanned. They share the fixed components, but tool-specific CSS/JS
     may still use raw colours (grep found 41 tool CSS files using --text-muted — now fine — and the QR green
     was one tool-specific case). Run `bash scripts/a11y-check.sh /path/` when touching a tool.
  3. F10 adoption: no tool calls setFieldError yet; errors still go via toast (now announced) or visual-only text.
  4. aria-live hygiene on per-frame progress updates (F12 note) not reviewed.
  5. Not tested: real screen readers, 400% zoom reflow, Windows High Contrast / forced-colors.
  6. Hero waves animate even under prefers-reduced-motion (deliberate, 2.3.3 is AAA). They pause off-screen and
     have no flashing; if a user reports discomfort, the switch is one line in initHeroWaves.
