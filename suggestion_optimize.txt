1. OG SOCIAL SHARE IMAGES (Per-tool social cards)
─────────────────────────────────────────────────
  WHY IT MATTERS: When someone shares a Toolity link on Twitter, LinkedIn,
  WhatsApp, Slack, or Discord, a generic or missing card hurts click-through.
  Tool pages currently lack og:image tags.

  THE FIX:
  - Create a high-contrast 1200×630 OG image in /assets/og-image.webp featuring
    the Toolity brand logo, slogan, and tagline.
  - Add to tool pages <head>:
      <meta property="og:image" content="https://toolity.in/assets/og-image.webp">
      <meta name="twitter:card" content="summary_large_image">
      <meta name="twitter:image" content="https://toolity.in/assets/og-image.webp">

  EFFORT: ~30 minutes (create OG asset once + batch script to inject into tool heads).


2. PRIVACY-FIRST TRUST BADGE ON ALL TOOL WORKSPACES
───────────────────────────────────────────────────
  WHY IT MATTERS: Most online converters upload files to random cloud servers.
  Toolity's biggest competitive advantage is 100% client-side privacy.
  Displaying a prominent, beautiful trust badge builds immediate user trust.

  THE FIX:
  - Add a small pill badge in the hero or workspace header of each tool:
      <div class="privacy-trust-badge">
        <iconify-icon icon="lucide:shield-check"></iconify-icon>
        <span>100% Local &amp; Private — Files Never Leave Your Browser</span>
      </div>
  - Style with subtle emerald/green or brand tint:
      background: rgba(16, 185, 129, 0.08);
      border: 1px solid rgba(16, 185, 129, 0.25);
      color: #10b981;

  EFFORT: ~20 minutes (add to shared CSS in main.css and tool templates).


3. TOOL COUNT BADGES ON HOMEPAGE CATEGORY CARDS
───────────────────────────────────────────────
  WHY IT MATTERS: Category cards on the homepage currently show no tool count.
  Visitors cannot immediately tell how many utilities exist in a category.
  A subtle "4 tools" pill signals completeness.

  THE FIX:
  - Add <span class="glow-card-count">4 tools</span> or <span class="glow-card-count">Coming Soon</span>
    inside each category card's metadata row on index.html.
  - Style as a compact pill alongside the category tag.

  EFFORT: ~20 minutes (HTML edit + small CSS rule in main.css).


4. SKIP-TO-MAIN-CONTENT ACCESSIBILITY LINK
──────────────────────────────────────────
  WHY IT MATTERS: Keyboard navigators and screen readers currently have to tab
  through all header navigation links on every page before reaching the tool.
  Standard a11y requirement that directly impacts SEO accessibility score.

  THE FIX:
  - Add as first child inside /components/header.html:
      <a href="#main-content" class="skip-link">Skip to main content</a>
  - Ensure every page's primary wrapper has id="main-content".
  - Style in main.css: visually hidden off-screen until focused by Tab key.

  EFFORT: ~15 minutes.

5. GLOBAL ⌘K / Ctrl+K COMMAND PALETTE & TOOL LAUNCHER
─────────────────────────────────────────────────────
  WHY IT MATTERS: The search bar only exists on the homepage. When a user is on
  a tool page (e.g., Favicon Extractor) and wants to jump to "Video to GIF",
  they currently have to go back to Home or open the mobile drawer.
  A global command palette (like Linear/Raycast/GitHub) makes the site feel
  world-class on desktop.

  THE FIX:
  - In main.js, listen for Cmd+K / Ctrl+K or '/' key globally.
  - Pop up a sleek frosted search modal overlay showing top tool results,
    category filters, and theme toggle shortcut.
  - Arrow key navigation + Enter to open.

  EFFORT: ~1.5 hours (lightweight modal in main.js + CSS).


6. RECENTLY USED TOOLS SHELF (LocalStorage Powered)
──────────────────────────────────────────────────
  WHY IT MATTERS: Power users frequently return for 2 or 3 specific tools
  (e.g., URL Cleaner, QR Generator). A "Recently Used" quick-chip row saves
  them from having to search or browse every time.

  THE FIX:
  - On tool page load, main.js appends the tool name/slug to a small JSON array
    in localStorage (max 4 items).
  - On the homepage or ⌘K launcher, render a "Recently Used" quick-action chip row:
      [⚡ URL Cleaner] [⚡ QR Generator] [⚡ Image Converter]

  EFFORT: ~45 minutes (pure JS, 0 dependencies).


7. BREADCRUMB & WEBAPPLICATION JSON-LD STRUCTURED DATA
──────────────────────────────────────────────────────
  WHY IT MATTERS: Google search displays breadcrumb navigation hierarchies
  and software application rich snippets (star ratings, 0 price, web application
  type) directly in search results, boosting organic click-through rates.

  THE FIX:
  - Add BreadcrumbList and WebApplication JSON-LD schemas to tool page heads:
      <script type="application/ld+json">
      {
        "@context": "https://schema.org",
        "@type": "WebApplication",
        "name": "Website Favicon Extractor",
        "url": "https://toolity.in/web/favicon-extractor/",
        "applicationCategory": "UtilitiesApplication",
        "operatingSystem": "All",
        "offers": { "@type": "Offer", "price": "0", "priceCurrency": "USD" }
      }
      </script>

  EFFORT: ~45 minutes via batch script.


8. "RELATED TOOLS" SUGGESTION ROW ON TOOL PAGES
───────────────────────────────────────────────
  WHY IT MATTERS: After a user finishes converting a video or grabbing a favicon,
  they often leave immediately. Showing 2-3 related tool cards below the guide
  section reduces bounce rate and increases pages per session.

  THE FIX:
  - Add a simple 2-card "Related Tools" row below the tool workspace before
    the FAQ/Footer section (e.g. on Video to GIF -> suggest GIF to Video & GIF Speed).

  EFFORT: ~1 hour across all tool pages.

9. COPY BUTTON MICRO-FEEDBACK (Checkmark Morph Animation)
─────────────────────────────────────────────────────────
  WHY IT MATTERS: Clicking "Copy" shows a toast, but changing the button icon
  momentarily from <iconify-icon icon="lucide:copy"> to a glowing green
  <iconify-icon icon="lucide:check"> provides immediate, tactile reassurance.

  THE FIX:
  - In main.js / tool scripts, when copy is triggered:
      btn.innerHTML = '<iconify-icon icon="lucide:check"></iconify-icon><span>Copied!</span>';
      btn.classList.add('copied-pulse');
      setTimeout(() => { resetBtn(); }, 1800);

  EFFORT: ~25 minutes.


10. DRAG-AND-DROP FULL-VIEWPORT HIGHLIGHT ON MEDIA TOOLS
────────────────────────────────────────────────────────
  WHY IT MATTERS: Users dragging files from their desktop often miss the small
  dropzone rectangle. When dragging anywhere over the browser window, the dropzone
  should expand with a glowing dashed border and "Drop file to convert".

  THE FIX:
  - In main.js / media tools, listen to window 'dragenter' and 'dragleave'.
  - Toggle a .drag-active class on the tool's upload container with a smooth scale
    and glowing highlight effect.

  EFFORT: ~30 minutes.


11. KEYBOARD SHORTCUTS FOR TOOL ACTIONS (Cmd+Enter to Run)
──────────────────────────────────────────────────────────
  WHY IT MATTERS: Power users expect keyboard triggers. Pressing Cmd+Enter
  (or Ctrl+Enter on Windows) inside an input field should immediately execute
  the primary action (Extract, Convert, Generate, Clean).

  THE FIX:
  - Add an input keydown listener in tool scripts:
      if ((e.metaKey || e.ctrlKey) && e.key === 'Enter') { runMainAction(); }
  - Display a subtle "[⌘↵]" badge inside or next to the main action button.

  EFFORT: ~30 minutes.


12. LIVE CHARACTER / WORD / BYTE COUNTERS ON TEXT INPUTS
─────────────────────────────────────────────────────────
  WHY IT MATTERS: Tools like URL Parameter Separator, Mailto Creator, and
  WhatsApp Link Creator deal with string lengths. Displaying a clean, real-time
  badge (e.g., "128 chars • 4 parameters") makes the tool feel responsive and precise.

  THE FIX:
  - Attach an input event listener that updates a small monospace count pill:
      <span class="input-stat-badge" id="input-stats">0 chars</span>

  EFFORT: ~25 minutes.


13. PRINT STYLESHEET (@media print)
────────────────────────────────────
  WHY IT MATTERS: When users try to print tables (e.g. format reference tables)
  or generated outputs, navigation bars, headers, floating pills, and ad slots
  clutter the physical printout.

  THE FIX:
  - Add to main.css:
      @media print {
        .site-header, .site-footer, .adsterra-ad-container,
        .mobile-bottom-pill-nav, .tool-toast, .tool-actions-toolbar {
          display: none !important;
        }
        body { background: #fff !important; color: #000 !important; }
        .workspace-card { border: none !important; box-shadow: none !important; }
      }

  EFFORT: ~15 minutes.

14. OFFLINE PWA CAPABILITY (manifest.json + Cache-First Service Worker)
───────────────────────────────────────────────────────────────────────
  WHY IT MATTERS: Because Toolity runs 100% in the browser with zero server API
  calls, the entire website can work completely offline! Adding a Web App
  Manifest and a lightweight service worker allows users to "Install" Toolity as
  a standalone Desktop or Mobile App that launches instantly with zero network.

  THE FIX:
  - Create /manifest.json with app metadata, theme color, and icons from /assets/favicons/.
  - Add a lightweight /sw.js service worker caching core assets (main.css, main.js,
    fonts, icons, HTML pages).
  - Register sw.js in main.js.

  EFFORT: ~1.5 hours.


15. HELPFUL CONTEXTUAL ERROR TOASTS (Better Input Validation)
─────────────────────────────────────────────────────────────
  WHY IT MATTERS: When a user enters an invalid URL or corrupted media file,
  showing generic "Error" or failing silently feels broken.
  Clear, human instructions (e.g., "That URL doesn't include a domain. Try typing 'google.com'")
  elevates user trust.

  THE FIX:
  - Standardize error validation messages across all input parsers using
    showGlobalToast("Tip: ...").

  EFFORT: ~30 minutes across tool files.
