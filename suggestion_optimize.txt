1. OG SOCIAL SHARE IMAGES (Missing on tool pages)
────────────────────────────────────────────────
  WHY IT MATTERS: When a user shares a tool URL on Twitter, LinkedIn, WhatsApp,
  or iMessage — no image shows up. Every social share is a dead preview card.
  The homepage has og:image but tool pages don't.

  THE FIX:
  - Create one generic og-image: a 1200×630 image with the Toolity logo,
    the brand color, and something like "Free Web Tools — Toolity.in".
  - Add this to EVERY tool page <head>:
    <meta property="og:image" content="https://toolity.in/assets/og-image.webp">
    <meta name="twitter:card" content="summary_large_image">
    <meta name="twitter:image" content="https://toolity.in/assets/og-image.webp">
  - Since you now have components/header.html, you can't inject this per-page
    automatically — keep it inline in each HTML <head> (it's already there for
    the homepage). Just add the og:image line to the ~10 tool pages missing it.

  EFFORT: 30 minutes. Use generate_image tool to make the OG image once.


2. CANONICAL URL TAGS (Missing everywhere)
──────────────────────────────────────────
  WHY IT MATTERS: Google may index both toolity.in/web/favicon-extractor and
  toolity.in/web/favicon-extractor/ (with and without trailing slash) as
  separate pages — causing duplicate content penalties.

  THE FIX: Add one line to every page <head>:
    <link rel="canonical" href="https://toolity.in/web/favicon-extractor/">

  Each page already has og:url — just add <link rel="canonical"> with the same
  URL. This is the single most impactful SEO tag missing from the site.

  EFFORT: Use a batch script (like the ones already used for migration) to add
  the canonical tag below the og:url tag in every file. ~20 minutes.


3. TOOL COUNT BADGES ON CATEGORY CARDS (Homepage feels empty)
──────────────────────────────────────────────────────────────
  WHY IT MATTERS: Category cards on the homepage show no tool count.
  Visitors can't tell if a category has 1 tool or 20. A small "4 tools" badge
  on each card signals richness and completeness.

  THE FIX: Add a small count badge to each category card:
    <span class="glow-card-count">4 tools</span>

  Style it as a subtle pill inside the card's info row. Update the count
  manually whenever a new tool is added. Low maintenance since tools are added
  infrequently.

  EFFORT: 30 minutes CSS + HTML edit.


4. SKIP-TO-MAIN-CONTENT LINK (Accessibility + SEO)
───────────────────────────────────────────────────
  WHY IT MATTERS: Screen reader users and keyboard navigators are forced to
  tab through the entire nav on every page. A skip link is a basic a11y
  requirement and signals quality to Google.

  THE FIX: Add as first child of <body> in components/header.html:
    <a href="#main-content" class="skip-link">Skip to main content</a>

  Then on each page add id="main-content" to the <main> tag.
  Style it visually hidden until focused:
    .skip-link { position: absolute; top: -40px; left: 1rem; z-index: 9999; }
    .skip-link:focus { top: 1rem; }

  EFFORT: 15 minutes.


5. FAVICON — UPGRADE TO PNG/ICO (Current is .webp)
────────────────────────────────────────────────────
  WHY IT MATTERS: The current favicon is served as .webp:
    <link rel="icon" type="image/webp" href="...Logo.webp">
  Safari (iOS & macOS) does not support WebP favicons reliably. The favicon
  may not appear in bookmarks, tabs, or home screen shortcuts on Apple devices.

  THE FIX:
  - Export the logo as a 32×32 .ico or .png file.
  - Replace the favicon tag:
    <link rel="icon" type="image/png" sizes="32x32" href="/assets/favicon-32.png">
    <link rel="apple-touch-icon" sizes="180x180" href="/assets/apple-touch-icon.png">
  - The 180×180 apple-touch-icon makes the site look great when added to iOS
    home screen — a real trust signal.

  EFFORT: 20 minutes (export + update head-common across all pages with script).

6. KEYBOARD SHORTCUT OVERLAY / COMMAND PALETTE HINT
────────────────────────────────────────────────────
  WHY IT MATTERS: The search bar already supports ⌘K / Ctrl+K shortcuts but
  there's no visible hint that this exists on most pages. Power users who
  discover this feel the site is "smart". Most never will.

  THE FIX:
  - On tool pages (where the search bar is not visible), show a subtle floating
    chip on the bottom-right: "⌘K Search tools"
  - Clicking it or pressing ⌘K focuses the search input / opens a mini search
    overlay, similar to how Linear or Raycast work.
  - This can be a 1-line overlay injected by main.js on non-homepage pages.

  EFFORT: ~2 hours (small overlay + CSS + wiring to existing search logic).


7. BREADCRUMB STRUCTURED DATA (JSON-LD for SEO)
─────────────────────────────────────────────────
  WHY IT MATTERS: Tool pages already have breadcrumb HTML (Home > Web Tools >
  Favicon Extractor). Adding JSON-LD breadcrumb structured data makes Google
  show this breadcrumb path directly in search results (as "breadcrumb rich
  results"), which significantly increases click-through rate.

  THE FIX: Add a small <script type="application/ld+json"> block to each tool
  page with the BreadcrumbList schema. Example for favicon-extractor:
    {
      "@context": "https://schema.org",
      "@type": "BreadcrumbList",
      "itemListElement": [
        {"@type": "ListItem", "position": 1, "name": "Home", "item": "https://toolity.in/"},
        {"@type": "ListItem", "position": 2, "name": "Web Tools", "item": "https://toolity.in/web/"},
        {"@type": "ListItem", "position": 3, "name": "Website Favicon Extractor"}
      ]
    }

  EFFORT: ~1 hour to write and add to all tool pages (scriptable).


8. "COPY LINK" BUTTON ON TOOL PAGES (Shareability)
────────────────────────────────────────────────────
  WHY IT MATTERS: If someone uses your tool and finds it useful, the friction
  to share it is: open address bar → select URL → copy → paste. One "Share"
  button drops that to one click.

  THE FIX: Add a Share button to the tool-actions-toolbar (already exists on
  every tool page, alongside Reset / Copy / Download):
    <button type="button" class="btn-toolbar-sm" id="btn-share-tool" title="Copy tool link">
      <iconify-icon icon="lucide:share-2" width="14" height="14"></iconify-icon>
      <span>Share</span>
    </button>

  Clicking it: navigator.clipboard.writeText(location.href) → shows toast
  "Tool link copied!". Falls back to Web Share API on mobile.
  Add this to main.js as a site-wide auto-bind since every tool page has
  the same toolbar structure.

  EFFORT: ~45 minutes (main.js + shared button in toolbar markup).


9. SCROLL PROGRESS INDICATOR ON LONG TOOL PAGES
─────────────────────────────────────────────────
  WHY IT MATTERS: Some tool pages are long (guide section, formats table,
  FAQ). A thin 2px brand-color progress bar at the top of the viewport (below
  the nav) shows reading progress and makes the page feel dynamic and alive.

  THE FIX: Add to main.js (runs on all pages):
    window.addEventListener('scroll', () => {
      const pct = window.scrollY / (document.body.scrollHeight - window.innerHeight);
      progressBar.style.transform = `scaleX(${pct})`;
    });

  One <div class="scroll-progress-bar"> injected by main.js below the header.
  CSS: position fixed, top: var(--header-height), height: 2px, background:
  var(--brand), transform-origin: left, will-change: transform.

  EFFORT: ~30 minutes.


10. DARK MODE SYSTEM — REMOVE FLASH ON INITIAL LOAD
────────────────────────────────────────────────────
  WHY IT MATTERS: On first visit, if the user's OS prefers dark mode but
  localStorage has no saved preference, there's a brief flash of white before
  the dark theme is applied. This feels unpolished and jittery.

  CURRENT STATE: main.js already applies the initial theme early (before
  DOMContentLoaded), but it runs after the HTML is rendered.

  THE FIX: Add one tiny inline <script> block to every page's <head> as the
  VERY FIRST script (before any external scripts):
    <script>
      (function(){
        var t = localStorage.getItem('toolity_theme') ||
          (window.matchMedia('(prefers-color-scheme:dark)').matches ? 'dark' : 'light');
        document.documentElement.setAttribute('data-theme', t);
      })();
    </script>

  This runs synchronously before any HTML renders, eliminating the flash
  entirely. This is the standard approach used by Vercel, Linear, and others.
  Add this to the common <head> block of all pages.

  EFFORT: ~20 minutes (add to each page head via batch script).

11. TOOL LAST-UPDATED DATE (Trust signal for returning visitors)
───────────────────────────────────────────────────────────────
  WHY IT MATTERS: Visitors can't tell if a tool was built last month or 3 years
  ago. A "Last updated: Sep 2026" line below the tool title adds immediate
  freshness signal and combats the "is this still maintained?" question.

  THE FIX: Add a simple line to the page-hero on each tool page:
    <span class="tool-updated-date">Updated September 2026</span>

  This is hardcoded — just update it when you actually change the tool.
  Style: small, muted, monospace, below the page-desc.

  EFFORT: 1 line per tool page. Very low.


12. RELATED TOOLS SECTION (Increases pages-per-session)
─────────────────────────────────────────────────────────
  WHY IT MATTERS: After using the YouTube Thumbnail Downloader, the user leaves.
  If you showed "You might also like: Favicon Extractor, URL Parameter Cleaner",
  they'd click and discover more tools. This reduces bounce rate and increases
  session depth — both SEO signals.

  THE FIX: Below the guide section on each tool page, add a small
  "Related Tools" row (2-3 cards in a horizontal scroll on mobile):
    <section class="related-tools-row">
      <h3>Related Tools</h3>
      <!-- 2-3 tool cards using existing .tool-card component -->
    </section>

  Pick related tools manually — they won't change often. No dynamic JS needed.
  Reuse the existing .category-glow-card or .tool-card component styles.

  EFFORT: ~1 hour per tool page, or 1 new CSS class + 8-10 hours total.


13. STRUCTURED DATA — WebApplication SCHEMA
────────────────────────────────────────────
  WHY IT MATTERS: Google has a WebApplication schema that can make your tool
  pages eligible for rich results (action buttons, ratings, etc.).

  THE FIX: Add a JSON-LD block to each tool page:
    {
      "@context": "https://schema.org",
      "@type": "WebApplication",
      "name": "YouTube Thumbnail Downloader",
      "url": "https://toolity.in/web/youtube-thumbnail-downloader/",
      "description": "...",
      "applicationCategory": "UtilitiesApplication",
      "operatingSystem": "Web",
      "offers": { "@type": "Offer", "price": "0", "priceCurrency": "USD" }
    }

  EFFORT: ~1 hour (template + add to each tool page).

16. EMPTY STATE ANIMATIONS
────────────────────────────
  CURRENT STATE: The preview viewport shows a static empty-state icon when
  no input is entered.

  THE FIX: Add a subtle CSS pulse/breathing animation to the empty-state icon:
    @keyframes breathe {
      0%, 100% { opacity: 0.4; transform: scale(1); }
      50% { opacity: 0.7; transform: scale(1.05); }
    }
    .empty-preview-icon { animation: breathe 3s ease-in-out infinite; }

  This makes the interface feel alive even before the user interacts.
  Pure CSS, zero JS, zero performance cost.

  EFFORT: 5 minutes per tool page. Add to main.css shared section.

18. PAGE TRANSITION — FADE IN ON LOAD

21. PRELOAD CRITICAL ASSETS
─────────────────────────────
  Add to every page <head>:
    <link rel="preload" href="/styles/main.css?v=2.3" as="style">
    <link rel="preload" href="/assets/Toolity.in Logo.webp" as="image">

  This tells the browser to fetch these assets immediately when parsing HTML,
  before it renders anything. Reduces Largest Contentful Paint (LCP).
  Zero risk, pure upside.

  EFFORT: 2 lines per page. Add via batch script.


22. DEFER NON-CRITICAL SCRIPTS
────────────────────────────────
  The Iconify CDN script currently blocks rendering:
    <script src="https://code.iconify.design/iconify-icon/2.1.0/iconify-icon.min.js"></script>

  Add defer attribute:
    <script defer src="https://code.iconify.design/..."></script>

  Iconify is a custom element — it handles deferred loading gracefully. Icons
  will render slightly after page paint but the page content will be visible
  sooner. Batch-scriptable change.

  EFFORT: Add "defer" to the script tag via batch script. 15 minutes.


23. IMAGE width/height ATTRIBUTES ON ALL ASSETS
────────────────────────────────────────────────
  The logo webp and mascot images should have explicit width and height
  attributes to prevent Cumulative Layout Shift (CLS) — a Core Web Vital.
  Most already have them — audit any remaining images.
